# NeoFinesse — Phase 7.1.3 Final Benchmark Cleanup & Freeze Report

## 1. Executive Summary & Architectural Progression

NeoFinesse provides an AI Finance Controller designed for autonomous financial reconciliation, root cause analysis (RCA), and evidence-constrained settlement variance investigation.

### Guiding Architectural Principle
> **"AI investigates. Tools retrieve. Evidence constrains. Deterministic verification decides."**

The multi-phase benchmark progression demonstrates how agentic tool use solves the fixed-evidence-pack bottleneck without sacrificing financial safety:

```text
Phase 5
Deterministic Financial Verification
(Evaluates fixed multi-constraint checks on available ledger records)
        ↓
Phase 6
AI Reasoning Over Bounded Evidence
(Proposes candidate hypotheses over an initial static evidence pack)
        ↓
Phase 7
Adaptive Agentic Investigation
(AI inspects state, identifies missing evidence, and actively invokes bounded tools)
        ↓
Phase 5 Verifier Retains Final Authority
(Every proposed hypothesis is independently recalculated and constraint-checked)
```

## 2. Explicit Metric Formulations & Denominators

Every reported metric is mathematically derived from the scenario-level execution matrix with unambiguous denominators:

| Metric | Mathematical Formula | Numerator | Denominator | Interpretation |
|---|---|---|---|---|
| **Correct Terminal Decision Rate** | $\frac{N_{\text{matching\_terminal\_decisions}}}{N_{\text{total}}}$ | Cases where final decision matches ground truth outcome | Total scenarios ($N=23$) | Primary accuracy metric measuring correct business outcomes. |
| **Observed Resolution Rate** | $\frac{N_{\text{resolved\_or\_delayed}}}{N_{\text{total}}}$ | Cases whose final status is `RESOLVED` or `VALID_DELAYED_CREDIT` | Total scenarios ($N=23$) | Proportion of variances resolved without human intervention ($47.8\%$). |
| **Escalation Rate** | $\frac{N_{\text{escalated}}}{N_{\text{total}}}$ | Cases whose final status is `ESCALATE` | Total scenarios ($N=23$) | Proportion of cases requiring human controller review ($47.8\%$). |
| **Partial Resolution Rate** | $\frac{N_{\text{partial}}}{N_{\text{total}}}$ | Cases with `PARTIALLY_RESOLVED` status | Total scenarios ($N=23$) | Proportion of cases with partial attribution ($4.3\%$). |
| **False Closure Rate** | $\frac{N_{\text{falsely\_resolved}}}{N_{\text{unresolvable}}}$ | Cases falsely marked `RESOLVED` when expected to escalate | Total unresolvable cases ($N_{\text{unresolvable}}=11$) | Probability of dangerous unauthorized financial write-off. |
| **False Escalation Rate** | $\frac{N_{\text{falsely\_escalated}}}{N_{\text{resolvable}}}$ | Cases falsely escalated when sufficient evidence existed | Total resolvable cases ($N_{\text{resolvable}}=12$) | Probability of unnecessary human escalation overhead. |
| **Honest Exception Rate** | $\frac{N_{\text{correctly\_escalated}}}{N_{\text{unresolvable}}}$ | Cases correctly escalated | Total unresolvable cases ($N_{\text{unresolvable}}=11$) | Ability of system to safely refuse closure when evidence is absent. |
| **Partial Attribution Accuracy** | $\frac{N_{\text{correct\_partial}}}{N_{\text{partial\_expected}}}$ | Cases correctly partially resolved | Total expected partial cases ($N_{\text{partial}}=1$) | Arithmetic and residual accuracy on partial deficits. |
| **Tool Request Validity** | $\frac{N_{\text{approved\_tool\_requests}}}{N_{\text{total\_tool\_requests}}}$ | Valid tool requests approved by validator | Total tool requests submitted by AI ($N_{\text{req}}=15$) | Proportion of valid queries generated by planner ($60.0\%$). |
| **Invalid Request Rejection Rate** | $\frac{N_{\text{rejected\_requests}}}{N_{\text{invalid\_requests}}}$ | Invalid requests safely rejected | Total invalid requests ($N_{\text{inv}}=6$) | Protection rate against malformed/missing entity requests ($100.0\%$). |
| **Tool Safety Rate** | $\frac{N_{\text{safe\_executions}}}{N_{\text{invalid\_requests}}}$ | Invalid requests causing no unsafe execution | Total invalid requests ($N_{\text{inv}}=6$) | Complete absence of execution side-effects on bad requests ($100.0\%$). |
| **Budget Compliance Rate** | $\frac{N - N_{\text{violations}}}{N}$ | Cases with zero budget violations | Total scenarios ($N=23$) | Guarantee that investigations do not exceed configured limits ($100.0\%$). |

> **Zero-Denominator Policy**: For any category where a denominator is zero (e.g. `UPI State Investigation` has $0$ unresolvable cases), the metric outputs **`N/A`**, never `0.0%` or `100.0%`.

## 4. Failure Taxonomy & Root Cause Analysis

### Phase 5 Failures (6 False Closures, 0 False Escalations)
All 6 Phase 5 failures occurred in adversarial scenarios where candidate records matched the monetary deficit but lacked underlying relational or lifecycle validity:
1. `AG-002`: Accepted decoy adjustment without verifying settlement batch membership.
2. `AG-005`: Accepted candidate refund without checking underlying `FAILED` lifecycle status.
3. `AG-009`: Closed variance without validating redundant/duplicate deduction candidates.
4. `AG-010`: Accepted external same-amount decoy flooded into the ledger view.
5. `AG-011`: Accepted gateway capture record despite contradictory bank dispute report.
6. `AG-013`: Attempted resolution across deep dependency chain without recursion bounds.

### Phase 6 Failures (1 False Closure, 4 False Escalations / Incomplete Resolutions)
1. `AG-001`: Fixed initial pack contained refund but lacked adjustment membership proof; credited only partial refund.
2. `AG-002`: AI hallucinated relation on decoy candidate present in fixed pack (`FALSE_CLOSURE`).
3. `AG-004`: Fixed pack lacked late authorization event; Phase 6 falsely escalated.
4. `AG-007`: Fixed pack flooded with same-amount candidates; Phase 6 could not prune decoys and escalated.
5. `AG-008`: Fixed pack lacked multi-hop line relationship; Phase 6 escalated.

## 7. Audit of AG-009 and AG-013 Semantics

### AG-009 (Redundant Tool Loop)
- **Mechanism**: The planner submits duplicate tool invocations. The `ToolRequestValidator` identifies the call signature in the executed history, blocking redundant database dispatch.
- **Baseline Failure**: Phase 5 does not inspect call repetition, allowing duplicate deduction attribution.

### AG-013 (Investigation Budget Enforcement)
- **Mechanism**: The scenario exercises a deep multi-hop relationship graph requiring $>3$ rounds and $>5$ calls.
- **Audit Verification**: Configured limit: `max_investigation_rounds=3`. Controller executes round 1, round 2, round 3, detects limit reached, marks `budget_exhausted=True`, sets `termination_reason="BUDGET_EXHAUSTED"`, and halts execution without unbound recursion.

## 9. Benchmark Limitations & Scope

The following limitations define the honest scope of this evaluation:
1. **Synthetic Financial Data**: Evaluated on procedurally generated, dual-hashed relational files (`seed=42`).
2. **Controlled Scenario Count**: Evaluated across 23 controlled variance scenarios.
3. **Explicit Ground Truth**: Ground truth causal links are explicitly known from generator injection.
4. **Benchmark vs Production Claim**: Phase 7 results represent architectural benchmark performance, NOT a claim of 100% real-world accuracy against unnormalized production ledgers.
5. **Local Execution Latency**: Measured latency ($0.29\text{–}1.64\text{ ms}$) reflects local pipeline dispatch and verifier evaluation; frontier LLM API latency ($500\text{–}2000\text{ ms}$ per round) is excluded.
6. **Mock AI Evaluation**: Phase 6 and Phase 7 evaluate agentic orchestration with controlled/mock AI behavior; live production model evaluation will occur in Phase 7.2.
7. **Bounded by Available Records**: Retrieval quality is strictly bounded by available ingested records.
8. **No Magically Recovered Records**: Missing or unrecorded cash transactions cannot be recovered by the agent.
9. **Provider-Specific Variance**: Production provider behavior (e.g. non-standard bank clearing formats, manual ledger adjustments) may differ from the normalized multi-source model.
